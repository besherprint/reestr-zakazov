# Реестр заказов — инструкция по запуску

## Что внутри
- Вкладки «Клиент» и «Заказ» с техкартами и историей выпусков
- Свой логотип (загружается через шестерёнку ⚙️ рядом с логотипом в шапке сайта)
- Вход по паролю — сайт закрыт от посторонних

---

## Шаг 0. Подключите общую базу данных (Supabase, бесплатно)

Без этого шага сайт не откроется — вместо него появится экран
«База данных не подключена». Это нужно, чтобы **все пользователи видели одни
и те же заказы и клиентов**, а не каждый свою локальную копию.

1. Зайдите на [supabase.com](https://supabase.com) → войдите (можно через
   GitHub) → **New project**. Выберите любое имя и пароль для базы (этот
   пароль не связан с паролем входа на сайт — он только для самой базы).
2. Дождитесь создания проекта (около минуты).
3. Слева откройте **SQL Editor** → **New query**, вставьте и выполните:

```sql
create table clients (
  id text primary key,
  name text not null,
  contact text,
  channel text,
  segment text,
  notes text,
  created_at timestamptz default now()
);

create table orders (
  id text primary key,
  name text not null,
  client_id text references clients(id) on delete set null,
  material text,
  sheet_size text,
  material_price text,
  material_price_unit text,
  cut_size text,
  print_spec text,
  post_press text,
  notes text,
  runs jsonb default '[]'::jsonb,
  created_at timestamptz default now()
);

alter table clients enable row level security;
alter table orders enable row level security;

create policy "allow all clients" on clients for all using (true) with check (true);
create policy "allow all orders" on orders for all using (true) with check (true);
```

   Эти политики открывают таблицы для всех, у кого есть ключ доступа — это
   нормально, потому что сам сайт уже закрыт паролем (шаг 1). Дополнительная
   защита на уровне базы — следующий уровень, см. раздел «Если понадобится» внизу.

4. Слева откройте **Project Settings → API**. Скопируйте:
   - **Project URL** → это будущая переменная `VITE_SUPABASE_URL`
   - **anon public** ключ → это `VITE_SUPABASE_ANON_KEY`

Обе переменные понадобятся на шаге 3, при деплое на Vercel.

## Шаг 1. Смените пароль перед запуском

Пароль по умолчанию — `reestr2026`. **Обязательно смените его.**

Откройте файл `src/components/PasswordGate.jsx`, найдите строку:

```js
const SITE_PASSWORD = import.meta.env.VITE_SITE_PASSWORD || "reestr2026";
```

Проще всего — задать пароль через переменную окружения при деплое (шаг 3), тогда
в самом коде пароль нигде не будет виден. Значение `"reestr2026"` — это просто
запасной вариант на случай, если переменную забыли задать.

**Важно:** это простая защита «от случайных людей», а не банковский уровень
безопасности — пароль всё равно попадает в код сайта, который выполняется в
браузере. Для доверенных лиц (сотрудников, партнёров) этого достаточно, но не
храните здесь секретные данные, которые нельзя показывать вообще никому.

## Шаг 2. Загрузите проект на GitHub

1. Зарегистрируйтесь на [github.com](https://github.com), если ещё нет аккаунта
2. Создайте новый репозиторий (New repository), например `reestr-zakazov`
3. Загрузите туда все файлы этого проекта (можно просто перетащить папку через
   веб-интерфейс GitHub — кнопка "uploading an existing file")

---

## Шаг 3. Разместите на Vercel (бесплатно)

1. Зайдите на [vercel.com](https://vercel.com) и войдите через GitHub
2. Нажмите **Add New → Project**
3. Выберите репозиторий `reestr-zakazov`
4. Vercel сам определит, что это Vite-проект — ничего менять не нужно
5. Разверните секцию **Environment Variables** и добавьте три переменные:
   - `VITE_SITE_PASSWORD` — ваш пароль для входа на сайт (например `Print2026!`)
   - `VITE_SUPABASE_URL` — Project URL из Supabase (шаг 0)
   - `VITE_SUPABASE_ANON_KEY` — anon public ключ из Supabase (шаг 0)
6. Нажмите **Deploy**

Через 1-2 минуты сайт будет доступен по адресу вида
`https://reestr-zakazov.vercel.app` — это и есть ваш постоянный адрес в интернете.

*(Альтернатива — [netlify.com](https://netlify.com), процесс почти идентичный:
Add new site → Import from Git → указать переменную окружения
`VITE_SITE_PASSWORD` в Site settings → Environment variables.)*

---

## Шаг 4. Логотип

После входа на сайт нажмите на шестерёнку ⚙️ рядом с иконкой в шапке →
«Загрузить логотип» → выберите файл. Логотип сохраняется в браузере того
устройства, с которого вы его загрузили.

---

## Как выдать доступ доверенным лицам

Просто дайте им ссылку на сайт и пароль. Все, кто вошёл, работают с одной и
той же базой в Supabase — заказ, добавленный с одного телефона, через
несколько секунд появится у всех остальных (данные обновляются автоматически
каждые 8 секунд).

---

## Если позже понадобится:
- **Свой домен** (например reestr.ваша-компания.uz вместо vercel.app) —
  покупается отдельно и привязывается в настройках Vercel/Netlify за 10 минут
- **Разные пароли/роли для разных людей** (например «только просмотр» для
  части сотрудников) — потребует полноценной авторизации через Supabase Auth
  вместо одного общего пароля
- **История изменений / кто что редактировал** — тоже реализуемо через
  Supabase, при необходимости можно добавить
